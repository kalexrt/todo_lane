# ADR 0003 — Replace the fixed ticket-status union with per-board columns
**Status:** Accepted
**Context:** The CONSTITUTION (convention #1) locks ticket status to the fixed string union `'todo' | 'in_progress' | 'done'` everywhere — a deliberate choice that kept the original single-board tracker minimal and gave status-transition gating a known, closed set to later rule over. The multiple-boards enhancement (feature 0003, PRD §S-0003.02) makes each board own its own workflow: a board's owner decides its columns (e.g. `Backlog` / `Done`, or `todo` / `in_progress` / `done`, or any others). A single global union can no longer describe every board's statuses, so the closed-set assumption that grounded convention #1 no longer holds. The CONSTITUTION's own hard rule ("never add ... new dependencies beyond the stack above without an ADR") and the LANE grounding rule ("Any change that needs to break a stated convention ... is ... a candidate ADR — never a silent divergence") require this decision to be recorded before the change is made.
**Decision:** Replace the fixed status union with **per-board columns**. A board (project) owns an ordered list of columns; each column is a pair of an immutable machine **slug** (the value stored as a ticket's status) and a mutable display **label**. A ticket's status is a `string` that must equal one of its board's current column slugs. The status-change seam — `PATCH /api/tickets/:id/status` backed by the single `TicketsService` status-change method — remains the only code path that may mutate a ticket's status (CONSTITUTION hard rule unchanged) and now validates the requested status against the ticket's board's columns, rejecting (400) any status that is not a column on that board. The **slug-not-display-string, not-numeric-code** discipline of convention #1 is preserved (a status is still a machine slug); only the *closed set* is opened to be per-board. The default project is seeded with the existing columns `todo` / `in_progress` / `done`, so tickets created before this change stay valid on upgrade with no data migration. Removing a column that still has tickets in it is rejected, so the invariant "a ticket's status is always one of its board's columns" can never be violated. Column data is persisted in SQLite alongside projects and tickets (ADR-0002), reached only through `ProjectsService` / `TicketsService` (BLUEPRINT boundary rule) — no new persistence layer or ORM.
**Consequences:** `TicketStatus` widens from a closed string union to `string` in both packages; the static `@IsIn(TICKET_STATUSES)` check on the status DTO is replaced by a non-empty-string DTO check plus a dynamic, board-aware validation in the service (a domain rule, owned by the service, not the DTO). The backend gains a columns data collection and a small column-management endpoint surface on projects; the `Project` API response gains a `columns` field. The frontend's hardcoded three-column board is replaced by a dynamic board that renders the active board's columns. Existing single-board tests that assume the fixed union are updated as part of this feature's TDD ledger. `docs/context/CONSTITUTION.md` (convention #1), `PRODUCT.md`, and `BLUEPRINT.md` are updated via `lane fold` **after** the feature lands — context docs are read-only during active feature work — to record the new status model and the columns collection.
